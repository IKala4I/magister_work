# ADR-0004 — Expo SDK 57 + RN 0.86 accepted; TypeScript pinned back to 5.9

- **Date:** 2026-08-24
- **Status:** accepted
- **Phase:** P1
- **Spec anchors:** specs/03 §2.1 ("Expo SDK 54+", "React Native 0.8x", "TypeScript 5.x
  strict", "pin exact versions at implementation time")

## Context

The P0 scaffold landed Expo SDK 57 / RN 0.86.2 / TypeScript 6.0.3 (the template defaults)
without an ADR. Expo 57 and RN 0.86 sit inside the spec's stated ranges; TypeScript 6 does not
("TypeScript 5.x"). Owner directive: record all three, and verify TS 6 against every pinned
tool — downgrade rather than work around any incompatibility.

## Decision

- **Expo SDK 57.0.16 / RN 0.86.2 / React 19.2.3: accepted.** Within "SDK 54+ / 0.8x"; New
  Architecture only, which the spec assumes.
- **TypeScript: downgraded 6.0.3 → 5.9.3.** Verification found a hard incompatibility:
  `openapi-typescript@7.13.0` — the P1 contract-sync tool (File 03 §6 step 1) — declares
  `peerDependencies: { typescript: "^5.x" }` and fails npm resolution against TS 6. Per the
  owner rule, the repo downgrades to the latest 5.x rather than forcing peers. This _restores_
  spec compliance (File 03 names TS 5.x); TS 6 had been an undocumented template artifact.
- `expo.install.exclude: ["typescript"]` declares the pin to Expo tooling (SDK 57 templates
  expect ~6.0.3); expo-doctor passes 21/21 with it.

## Verification (2026-08-24)

| Tool                | Version          | TS 5.9.3 evidence                                                                           |

| openapi-typescript  | 7.13.0           | peer `^5.x` satisfied; generated output compiles under `--strict`                           |

| jest-expo / jest    | 57.0.4 / 29.7.0  | full suite green after downgrade                                                            |
| typescript-eslint   | 8.67.0           | lint green after downgrade                                                                  |
| expo / RN toolchain | 57.0.16 / 0.86.2 | `tsc --noEmit` green; expo-doctor 21/21                                                     |
| supabase gen types  | —                | emits plain type declarations; validated by the P1 contract-sync gate when generation lands |

## Consequences

One committed version family per tool; TS 6 upgrade is deferred until openapi-typescript
publishes TS-6 peer support (track alongside the ADR-0003 jest-30 TODO). Drizzle's pinned
version is chosen at P2 install; 0.45.2 is the verified-compatible line.
