# Конвеєр складання магістерської роботи

`full.md` → `.docx` за стандартом НУБіП / ДСТУ 3008, із перевірками.

Головне правило: **жоден рядок прози не набирається руками** — текст читається з `full.md`.
Руками зроблено лише те, що не має текстового вигляду: формули (`formulas.py`) і реєстр
погоджених правок (`registry.json`).

## Запуск

```bash
./run_all.sh ../text/full.md ../formatter-brief.md /Users/vladyslav/Workspace/MagisterDocs
```

Третій аргумент — тека **MagisterDocs поза репозиторієм** (власник, 2026-09-29): звідти
приватні дані (`private/titulka.json` — імена для титулки й анотацій; `full.md` лишається з
плейсхолдерами), знімки рисунка 4.1 (`figures/4.1/`), туди — результат (`build/`: .docx, PDF,
звіт, аудит, рендери). Там само `sources/draft.docx` (вхід `assemble.py --draft`) і `golden/`
(еталон регресій). Будь-що з цього в репозиторій не потрапляє; `verify.py` падає, якщо приватне
ім'я опинилося в `full.md`.

або окремо (з цієї теки, `DOCS=/Users/vladyslav/Workspace/MagisterDocs`; `uv run` бере Python і пакети
з власного проєкту теки):

```bash
uv run python render_figures.py --src ../text/full.md --out $DOCS/build/figures --docs $DOCS     # рисунки
uv run python build.py  --src ../text/full.md --brief ../formatter-brief.md --out $DOCS/build/hourwell.docx --report $DOCS/build/report.json --figures $DOCS/build/figures --private $DOCS/private/titulka.json
uv run python verify.py --src ../text/full.md --brief ../formatter-brief.md --docx $DOCS/build/hourwell.docx --figures $DOCS/build/figures --private $DOCS/private/titulka.json
uv run python check_legend_symbols.py ../text/full.md
uv run python audit_markdown.py ../text/full.md --out $DOCS/build/audit.md
uv run python regress.py $DOCS/golden/hourwell.docx $DOCS/build/hourwell.docx   # після зміни конвеєра
uv run python make_pdf.py $DOCS/build/hourwell.docx $DOCS/build/hourwell.pdf      # PDF для читання, зі змістом
```

`cmp` чи хеш усього .docx для порівняння не годяться: у zip записано час складання, тож
два однакові документи різняться байтами архіву. `regress.py` порівнює вміст частин.

Залежності. **Python і пакети — не з машини**, а з проєкту uv цієї теки: `pyproject.toml`
(python-docx 1.2.0, lxml 6.1.1, точні версії) і `uv.lock`, Python 3.12 лише керований uv
(`python-preference = "only-managed"`) — видалення системного Python чи дистрибутива на кшталт
Anaconda збірку не ламає. `run_all.sh` запускає все через `uv run --locked`. Із системи потрібні
тільки `uv`, `pandoc` (LaTeX → OMML для формул) і `unzip`; `run_all.sh` друкує версії першим
рядком. **pandoc** формує OMML формул, тож його версія може зсунути формули: еталон відтворюється
частина до частини з pandoc 3.8, 3.8.2.1 і 3.11 (перевірено 2026-09-28); після оновлення pandoc —
`regress.py` проти еталона.

**Рисунки й PDF** теж не з машини, окрім кількох системних інструментів. Mermaid — `render/`
(окремий npm-проєкт: mermaid-cli 12.0.0 точно, `package-lock.json`, власний chrome-headless-shell
у `render/.cache`; `run_all.sh` виконує `npm ci`, якщо його немає) — потрібні `node`/`npm`.
PlantUML — `plantuml-1.2026.8.jar`, закріплений за SHA-256 і завантажений у `render/.tools`
при першому запуску; розкладка smetana, тож Graphviz не потрібен, — потрібна Java (17+). PDF —
LibreOffice 26.8.0 (macOS aarch64), закріплений за SHA-256, розпакований у `render/.tools`
(≈ 800 МБ) із власним профілем; macOS потрібна для `hdiutil`. `render/.cache` і `render/.tools`
git-ignored.

## Рішення, закладені в код, і чому

**Верстка.** А4; поля 30 / 10 / 20 / 20 мм; Times New Roman 14; інтервал 1,5; абзац 1,25 см;
по ширині. Розділи — Heading 1 з нової сторінки, по центру; підрозділи — з абзацного відступу;
кожен додаток — з нової сторінки (перший — на сторінці «ДОДАТКИ»).
Номер сторінки вгорі праворуч, на титулці немає. ЗМІСТ — поле Word (F9), сам він у зміст не йде.
Підпис таблиці — над нею зліва, рисунка — під ним по центру.

**Формули** — справжні рівняння OMML, не текст і не зображення. Кожна формула — невидима
таблиця: `[мітка (C1)…(C5)] | формула | номер`. Номер у власній комірці не може «з'їхати»
вниз чи вліво, а вираз, ширший за комірку, Word переносить усередині неї. Формула в комірці —
`oMathPara`. Мінус — U+2212. Кегль: 12 пт для довгих, (2.3), (2.6), (2.7) розбиті на два
рядки по 14 пт. Індекси — справжні підрядкові позиції; `clip[0,1]` — дужки на базовій лінії.

**Таблиці** розбираються за правилами GFM: `\|` — риска всередині комірки, риска без скісної —
роздільник. Зламане екранування (скісна, відокремлена від риски) **валить складання**, а не
лагодиться мовчки. Ширина стовпця — спершу вміщається найдовше слово, решта пропорційно
до обсягу тексту; кегль 12 → 11 → 10, нижче 10 не опускається. Числові стовпці — по центру.

**Код** (огорожі ```, Додаток Ж) — дослівно, Courier New, без розбору розмітки: апостроф у
`f'y_{t.id}'` — синтаксис. Порожні рядки всередині блоку — теж код (у SQL Додатка Г вони
відділяють групи інструкцій; до 2026-09-28 випадали), крайні відкидаються. Кегль — найбільший,
за якого найдовший рядок вміщається в 170 мм.

**Розмітка в прозі**: `**жирний**`, `` `код` ``, `_курсив_` — рекурсивно, тож вставка коду
всередині курсиву обробляється. Курсивом стає лише проза: ідентифікатор чи шлях із парою
підкреслень — ні. Підписи таблиць, рисунків і лістингів та список джерел — поза розбором.

**Нормалізація** — три масові заміни, погоджені з автором, кожна із запобіжниками, що валять
складання: десяткова кома й мінус (лише в суто числових комірках таблиць і не в стовпцях,
чий заголовок називає розділ чи підрозділ: `3.7` там — номер підрозділу; англомовна
анотація свідомо з крапкою — див. docstring `_decimal_comma`); апостроф `'` → `’` (крім коду,
адрес і вставок у зворотних лапках). Заміна не може змінити довжину рядка, будь-яку пару
символів поза трьома дозволеними, чи зачепити рядок `keep-verbatim`.

**Реєстр правок** прив'язаний до тексту, не до номерів рядків. Ненайдений або неоднозначний
якір валить складання. Правка, що вже є в джерелі, не застосовується вдруге.

**Рисунки** рендеряться з вихідного коду (`../text/diagrams/*.mmd`, `*.puml`) кроком `run_all.sh`
і стають на місце плейсхолдера «[МІСЦЕ ДЛЯ РИСУНКА N]»; рисунок без рендера лишається
плейсхолдером. Найдрібніший підпис рисунка на папері — **не менше 8 пт** (власник, 2026-09-29):
`render_figures.py` вимірює його в SVG того самого рендера (явні розміри тексту з урахуванням
перекриттів у `render/mermaid.css` — Mermaid малює номери кроків фіксованими 12 px, тут вони
15 px) і з масштабом, з яким рисунок стане в свою область (книжкова 170 × 240 мм, альбомна
257 × 150 мм), і падає, якщо менше; `verify.py` перераховує те саме з ширини зображення в
готовому .docx і перевіряє орієнтацію сторінки. Що не
вміщується: або **аркуші** — рядок-маркер `%% аркуш` у вихідному файлі на природній межі сценарію
(підпис із `full.md` — під першим аркушем, далі «Рисунок N, аркуш k», нумерація кроків
продовжується, учасники, яких аркуш не має, не малюються), або **альбомна сторінка** — розділ
альбомної орієнтації лише для рисунка, корінець 30 мм стає верхнім полем, а номер сторінки —
внизу праворуч (правий верхній кут аркуша); розрив розділу стоїть у сусідньому абзаці, без
зайвого порожнього. Один масштаб на всі
аркуші рисунка. Підписи повідомлень Mermaid переносяться явними `<br/>` під час рендера (власне
перенесення Mermaid рахує висоту замало й кладе рядок на стрілку); у вихідному файлі слова ті самі.
PlantUML обрізає зображення ширші за 4096 px, тому ліміт знято (`-DPLANTUML_LIMIT_SIZE`). Знімки
(рисунок 4.1) — з теки `../figures/4.1`, сіткою до чотирьох у ряд, у порядку назв файлів.

**PDF.** ЗМІСТ — поле Word, яке звичайна конвертація не оновлює; макрос LibreOffice у власному
профілі оновлює покажчики двічі й експортує PDF, а при помилці завершує LibreOffice (інакше
безголовий макрос зависає на невидимому діалозі).

## Що гарантує кожна перевірка — і чого не гарантує

| Перевірка                 | Гарантує                                                                                                                                                                                                                                                                                                | НЕ гарантує                                                                              |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `verify.py`               | дорогою від `full.md` до .docx нічого не переписано й не загублено; таблиці — комірка до комірки від сирого джерела, кожна заміна оцінена власними правилами; блоки коду — рядок до рядка, з порожніми; рисунки — саме ті рендери на своїх місцях (SHA-256), аркуші з підписами, зайвих зображень немає | що сам `full.md` правильний: зіпсоване джерело й зіпсований документ збігаються ідеально |
| `check_legend_symbols.py` | легенда не пережила символ, який пояснює; кожен запуск доводить негативним контролем, що без символу в таблиці перевірка падає, і падає, якщо легенди не знайдено                                                                                                                                       | інших видів неузгодженості таблиці з текстом                                             |
| `audit_markdown.py`       | помічено все, що лишило слід у символах розмітки                                                                                                                                                                                                                                                        | поломку без сліду — з'їдене цілком слово чи рядок                                        |
| `regress.py`              | зміна конвеєра змінила документ рівно там, де показано                                                                                                                                                                                                                                                  | що зміна правильна — це вирішує людина, дивлячись на показане                            |
| `render_figures.py`       | найдрібніший підпис кожного рисунка на папері ≥ 8 пт                                                                                                                                                                                                                                                    | що рисунок змістовно правильний — це перевіряє людина проти тексту                       |

Три уроки, заради яких ця таблиця існує:

1. **Перевірка, що ділить код із перевіреним, не бачить його помилок.** `verify.py` колись
   розбирав таблиці тією самою функцією, що й складальник, і тому не помітив, що складальник
   прибирав пробіл у «за змінного |A_m(x)|». Тепер у `verify.py` власний незалежний розбір.
   Те саме стосується правил: `verify.py` звіряв документ із джерелом _після_ нормалізації
   складальника і тому казав OK, коли правило коми друкувало номер підрозділу «3.7» як «3,7»
   (2026-09-28). Тепер звірка йде від сирого джерела, а дозволеність кожної заміни
   `verify.py` оцінює сам — зокрема знає номери підрозділів із заголовків документа.
2. **Інструмент перевірки теж буває дефектним.** Тричі за історію роботи дефект сидів
   в інструменті, а не в джерелі: звуження правила курсиву зламало опис рисунка 3.3;
   «зшивання» комірок прибирало пробіл; наївне `split('|')` у перевірках роками показувало
   правильне `\|` як розрізану таблицю. Щоразу рятувала інша, незалежна перевірка.
3. **Перевірка, яка ніколи не падала, нічого не довела.** `check_legend_symbols.py` шукав
   легенду з довгим тире «—», а в тексті з 2026-09-13 лише коротке «–»: єдину легенду
   («◐ – …» під табл. 1.2) він не знаходив, і «помилок: 0» було порожнім. Тепер він приймає
   обидва тире, падає, якщо легенд не знайдено, і на кожному запуску прибирає символ із
   таблиць, щоб переконатися, що на цьому впаде.

## Регресія: як змінювати конвеєр

1. Зберегти еталон: останній прийнятий .docx **разом із точним `full.md`** і рендерами рисунків
   (`golden/figures`), з яких його зібрано.
2. Змінити код.
3. Зібрати тим самим `full.md` з тими самими рендерами (`--figures golden/figures`) і запустити
   `regress.py ЕТАЛОН НОВИЙ`. Зображення `regress.py` порівнює за SHA-256 байтів і розміром на
   сторінці; зміну діаграми чи рендерера видно як зміну конкретного зображення.
4. Кожну показану розбіжність або прийняти як намірену, або виправити код.

Код виходу `regress.py` — 0 лише коли документи ідентичні або рівні змістовно.
Відновлений 2026-09-28 конвеєр доведено саме так: на `full.md` стану перед PR #80 він дав
документ, **байт у байт ідентичний** збірці POVNA. Єдина подальша намірена зміна — розбір
таблиць за GFM — змінила рівно одну комірку, і цю зміну видно в `regress.py`.

## Відомі обмеження

- `formulas.py` — ручна робота. Якщо змінюється формула в джерелі, її треба змінити і тут;
  `verify.py` ловить лише загублені кириличні слова, а не змінені індекси чи числа.
- LibreOffice верстає рівняння тісніше за Word: вихід за поле, видимий у Word, у PDF з
  LibreOffice може не проявитися. Остаточне слово щодо формул — за Word.
- Символ ◐ набрано шрифтом Segoe UI Symbol; на системі без нього Word підставить свій.
- `audit_markdown.py` сигналить `clip[0,1](` як синтаксис посилання — це відомий хибний сигнал
  і водночас живе нагадування, що саме це місце інструменти вже раз прочитали хибно.
