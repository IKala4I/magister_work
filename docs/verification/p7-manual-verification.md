## 2. What the tests establish (requirement → evidence)

- **specs/07 §3.4.1 rows 1–10** — one Deno test per row in `_shared/rewards_test.ts` (in-window
  finish 1.0; done-in-slot 1.0; abandoned ≥ 50 % 1.0; abandoned < 50 % r = f; Σ over sessions;
  ±15 min boundary at 15:01; off-slot 0.3 daily-only; late-start finish = off-slot; lapse 0.0
  with `status = lapsed`; another day's completion ≠ this block; skip 0.0 → `rejected`; facts beat
  plans; override pair 0.1/0.7 with origin/target features; one pair per placement; displaced /
  expired rows never produce a tuple; `conflict_flag` → excluded with value kept; idempotent
  re-run; correction inside/outside the 7-day window; ratings and `lapse_observed` never reward).
- **§3.4.2 23:55-local authority, DST** — `p7_feedback_test.sql`: r1 due at exactly 23:55:00 EEST
  and not 23:54:59; r2 (slot ending 01:30 on the fall-back day) due only at 23:55 **EET** on the
  25th, not at the old +03 boundary; r4 due at 23:55 EEST on the spring-forward day; a Los
  Angeles row in the same sweep at 06:55Z; displaced/attributed/expired never due; service-only
  execute; cron job present; tick is a no-op without Vault secrets; `duration_estimates` RLS.
- **Two-phase semantics + outage** — `handler_test.ts`: instant writes+delivers; backend-key
  path (P8's sync-resolve); service down → tuple stored undelivered, re-run does not duplicate,
  the daily sweep delivers once the service answers; `not_configured` (no host) keeps tuples
  pending without error; move → pair + computed target (MO.wd.fresh at 10:00 Kyiv) + row moved;
  daily slice → off_slot/lapsed with statuses and `attributed_at`, re-run is a no-op; correction
  rewrites in place and re-sends with `correction = true` and the original `attributed_at`;
  duration estimator folds finished sessions once (monotone marker).
- **Service math** — `test_blend.py`: River (Squared loss, lr/2) equals the unprojected step to
  1e-12 over three cases and a two-step trajectory; the 2-simplex projection equals a brute-force
  nearest point; `test_feedback.py`: the blend moves toward the reward, persists with the batch
  version, ignores excluded tuples, and a correction-triggered rebuild reproduces the online
  trajectory to 1e-12; `test_energy.py`: rung-2 helpers incl. decay relaxing a personal cell.
  Pre-existing P5 tests still pin SM ≡ naive inverse, rebuild ≡ sequential updates, decay
  half-life, rebuild-after-correction ≠ downdate.
- **Client facts** — `feedbackDao.test.ts` on real SQLite: session lifecycle with a pause
  (focused ms excludes the pause; task done; four facts through the outbox with shared op_ids);
  abandon leaves the task open; rating is a label; Done/Skip/Move/"I did it" payloads; lapse scan
  marks only ended, session-less, undone blocks and is idempotent; **DST**: on the Kyiv fall-back
  night the pre-change 03:30–04:30 slot lapses at the second 04:00 while the post-change one does
  not; third consecutive lapse/skip surfaces the diagnostic; no payload carries the title, no
  payload has a `reward` key; server patches mirror status/slots/features.
- **UI** — `today.test.tsx`: action row, Start → Focus tab, Move picker with 15-min snap, lapsed

## 2b. Live routing check on the hosted project (2026-08-27)

Both functions deployed (`supabase functions deploy attribute-rewards` / `plan-request`); the P7
migrations pushed (`20260827150000_p7_feedback`, `20260827160000_p7_sweep_bearer`). `curl` to
`/functions/v1/attribute-rewards` with no headers, or with `apikey` only → **401 from the gateway**
(`{"error":"unauthorized","detail":"missing bearer token"}` — not the handler's message, even
though `verify_jwt = false`); with `Authorization: Bearer <publishable key>` → the handler answers
(401 `{"error":"unauthorized"}`: no backend key configured, no user). Consequence: the cron tick
sends the publishable key as bearer (+ `apikey`) and the third Vault secret is required
(HANDOFF ⛔ 2). Establishes: deploy + routing + the handler's own auth gate. Does not establish:
a successful daily run (needs the Vault secrets) or delivery (needs the host).
